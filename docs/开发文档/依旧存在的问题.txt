本轮已收口项

1. invoke / tool-call 并发语义已经从“设计层并发”收口为“运行时真实并发”。
   - invoke fan-out 现在按分支并发提交，首错触发其余分支 cooperative cancellation。
   - tool-call 同轮并发明确为 snapshot isolation + deterministic merge。
   - 图级聚合态已统一为 DELEGATING，并明确它不是 subgraph lifecycle。

2. 多 agent 的核心分流不再依赖 tool_scope / _tool_scope。
   - session controller 模板已去掉 `tool_scope`。
   - 运行时按 `container_key -> runtime tool executor` 做显式绑定。
   - `ToolCapabilityExecutor` 仍是 allowlist 包装器，但文档已明确它不是独立 sandbox。

3. runtime graph 的结构 ownership 已收口到 Instantiator。
   - REST 执行入口先显式创建 runtime graph，再以 attach-only recorder 挂接。
   - Recorder 不再预创建 topology containers，也不再承担结构补偿创建职责。

当前仍保留的 follow-up

1. 多 agent 仍不是强隔离 runtime。
   - 当前边界仍主要是 in-process runtime binding、capability policy、memory scope 与 shared-host quota。
   - 权限、超时、崩溃传播、资源配额的治理边界仍弱于真正独立 sandbox。

2. Scratchpad 的 legacy 兼容层仍在。
   - 旧图的共享视图兼容逻辑尚未硬切，需要后续迁移或版本标记后再删除。

3. run-level state 与 trace-level state 仍是双轨。
   - `agent_runs` 负责 run lifecycle，recorder 负责 graph trace。
   - 后续若接远端 runtime、断点恢复、多租户限额，仍需进一步明确 source of truth。

4. quota / memory policy 仍偏框架化。
   - policy id、memory scope ref 与 capability allowlist 已接通。
   - 但跨分支 / 跨 agent 的资源仲裁、严格 memory contract 还没有完全落地。
