目标
  把当前“能创建基础拓扑对象”的页面，提升成一个真正可用的拓扑建模器，满足这 4 条主链路：

  1. 用户能快速创建一个新拓扑图。
  2. 用户能在一个页面里完成图、容器、节点、边的完整建模。
  3. 用户能在执行前完成结构校验并看懂错误。
  4. 用户能把模板稳定执行，并能看结果与问题。

  现状判断
  当前页面已经有基础骨架：

  - 图、容器、节点、边的基础 CRUD 已有。
  - 画布展示、布局拖动、属性面板、结构查看、执行入口已接通。
  - 后端模板执行接口已存在。

  但它还缺 3 类能力：

  - 基础可用性缺口：图属性保存有 bug，校验入口缺失，创建表单字段太少。
  - 建模效率缺口：大量操作要先创建空壳，再去右侧补字段。
  - 专业编辑器缺口：画布不能直接创建/连线/重排建模。

  所以完整方案应该分层推进，而不是一次性重做。

  完整方案
  第一阶段：修到“可用”
  目标是让这个页面能被真实用户稳定使用。

  1. 修图属性编辑

  - 修正图属性保存逻辑，graph 用 name 校验，不再误校验 label。
  - 图属性面板支持编辑：
    name、description、status
  - 只读展示：
    graph_id、graph_type、version、created_at

  2. 增加拓扑校验入口

  - 在页面工具栏增加“校验拓扑”按钮。
  - 调用 validateTopologyStructure(graphId)。
  - 展示分 3 类结果：
    通过
    警告
    错误
  - 错误要能定位到对象：
    容器、节点、边、表达式。
  - 校验结果支持点击后高亮相关对象。

  3. 完善新建表单

  - 新建图：
    name、description
  - 新建容器：
    container_key、label、role_type、order_index、config_json
  - 新建节点：
    container_id、node_key、label、node_type、role_type、order_index、config_json、input_schema_json
  - 新建边：
    source_node_id、target_node_id、edge_type、label、condition_expr、order_index、config_json

  4. 前端校验补齐

  - 必填校验。
  - JSON 格式校验。
  - 数值范围校验。
  - 唯一性提示尽量前置：
    container_key
    node_key
  - 边创建前做基础限制：
    不能自环
    不能缺源/目标
    同类型重复边给提示

  5. 创建后的引导

  - 创建新图后自动选中。
  - 空图状态给出下一步指引：
    先建容器 -> 再建节点 -> 再连边 -> 再校验 -> 再执行。
  - 如果图里没有 start/end，顶部直接给轻提示。

  第二阶段：修到“高效”
  目标是减少弹窗+属性面板之间来回切换。

  1. 右侧属性面板增强

  - 容器属性也纳入 inspector，而不只支持图/节点/边。
  - 支持直接改：
    container_key、label、role_type、order_index、config_json
  - 节点和边面板中增加更清晰的 schema/config 编辑器。

  2. 批量操作

  - 批量删除节点。
  - 批量调整节点归属容器。
  - 批量修改 order_index。
  - 批量导入简单 JSON 拓扑定义。

  3. 更好的结构可视化

  - 左侧图列表支持搜索。
  - 当前图显示校验状态徽标：
    draft
    valid
    invalid
  - 画布上节点类型、边类型、跨容器关系区分更明显。
  - 条件边显示条件摘要。

  4. 更好的错误反馈

  - 后端报错统一转成用户可读文案。
  - 校验失败时直接在画布高亮对应对象。
  - 执行失败时展示失败节点、条件错误、最终 trace 摘要。

  第三阶段：做成“专业编辑器”
  目标是提升建模体验，而不是只靠表单。

  1. 画布直接建模

  - 双击空白区域新建节点。
  - 拖拽节点端点直接连边。
  - 画布工具栏支持：
    新建节点
    新建容器
    自动布局
    对齐
    缩放到适配

  2. 容器交互增强

  - 拖拽节点进容器自动归属。
  - 从容器内拖出节点自动取消归属。
  - 容器支持 resize。
  - 容器内节点自动网格/流式排列。

  3. 边编辑增强

  - 直接点击边标签修改。
  - 条件边、默认边有不同视觉规则。
  - 一个节点多出口时，默认边自动排最后。
  - 支持“设为默认边”。

  4. 建模辅助

  - 自动补 start/end 模板。
  - 常用拓扑模板预设：
    线性流程
    条件分支
    人工审核
    多容器协作
  - 表达式编辑辅助：
    变量建议
    函数建议
    语法提示

  第四阶段：执行与调试闭环
  目标是让它不只是“画图”，而是“建模并运行”。

  1. 执行前检查

  - 如果校验未通过，默认禁止执行。
  - 执行前展示检查清单：
    是否有单一 start
    是否至少一个 end
    是否存在无后继节点
    条件表达式是否合法

  2. 执行配置面板

  - 输入 payload
  - 最大步数
  - 运行时图名称
  - 运行时图描述

  3. 执行结果面板

  - 展示状态：
    succeeded
    failed
    suspended
  - 展示运行时图 ID
  - 展示 trace 时间线
  - 高亮执行路径
  - 展示最终输出

  4. 调试能力

  - 支持从失败节点回看输入/输出。
  - 支持查看每一步条件判断结果。
  - 支持导出执行 trace JSON。

  页面结构建议
  一个稳定的三栏布局最合适：

  1. 左栏：图列表

  - 项目切换
  - 图搜索
  - 新建图
  - 图状态与更新时间

  2. 中栏：画布

  - 容器、节点、边可视化
  - 工具栏：
    新建容器
    新建节点
    新建边
    校验
    执行
    刷新
    自动布局

  3. 右栏：属性与结果

  - Tab 1：属性
  - Tab 2：校验结果
  - Tab 3：执行结果

  这样比把所有结果都塞弹窗更稳。

  接口与数据层建议
  前端不需要新建很多新 API，优先复用现有接口：

  - 已有：
    createGraph
    updateGraph
    createContainer
    updateContainer
    createNode
    updateNode
    createEdge
    updateEdge
    getGraphDetail
    getTopologyStructure
    validateTopologyStructure
    executeTopology

  建议补两个前端层能力：

  1. 一个 normalizeGraphEditorPayload() 工具

  - 统一处理 JSON 字段、空字符串、数字字段。

  2. 一个 topologyEditorStore 或组合式函数

  - 管理：
    当前图
    选择对象
    校验结果
    执行结果
    loading/error 状态

  这样 ExecutionTopologyTemplate.vue 不会继续膨胀。

  实施顺序
  我建议按这个顺序做：

  1. 修图属性保存 bug。
  2. 加“校验拓扑”按钮和结果展示。
  3. 扩展新建容器/节点/边表单字段。
  4. 让 inspector 支持容器编辑。
  5. 整理状态管理，拆出 composable/store。
  6. 做执行结果面板，不只弹 raw JSON。
  7. 再做画布直连建边和快捷建模。

  这个顺序风险最低，且每一步都能交付。

  验收标准
  做到“第一阶段 + 第二阶段前半”后，我认为就可以算“前端新建拓扑图功能齐全”：

  - 能新建图并编辑图属性。
  - 能新建容器、节点、边，且字段足够。
  - 能修改容器、节点、边属性。
  - 能查看和执行前校验拓扑。
  - 能执行模板并看到清晰结果。
  - 常见错误能被前端或校验层提前拦住。
  - 不需要靠后端报错来指导用户建模。
