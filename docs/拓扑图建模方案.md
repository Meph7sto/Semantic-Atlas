# 拓扑图执行引擎实现方案

## 背景

本实现方案基于 Agent方案.md 规范构建完整的拓扑图执行引擎。系统采用四层架构（session、execution、domain、data），以容器、节点和边为核心执行模型。

目标是实现驱动数据库中定义的拓扑图的实际执行逻辑，通过结构化执行流程实现多智能体协作。

## 问题

现有代码库拥有完整的数据模型（`TopologyStructure`、`AgentContainer`、`ContainerNode`、`CrossContainerEdge`）和数据库表，但缺乏实际运行拓扑图的核心执行引擎。当前实现仅包含结构，没有运行时执行逻辑。

## 解决方案

**复用现有前端组件和后端执行引擎**：
- 前端：`ExecutionGraphCanvas`、`ExecutionGraphInspector`、`ExecutionTopologyTemplate` 已实现完整功能
- 后端：节点推进、状态管理、追踪等能力已在 `RuntimeGraphRecorder` 中实现
- 只需将这些组件暴露为通用拓扑编辑器功能
- 拓扑模板保存到数据库后，可通过现有执行引擎直接执行

## 实现计划

### 第一阶段：复用现有组件（第 1 周）

**现有可复用组件：**

**文件：`frontend/src/components/alpha/ExecutionGraphCanvas.vue`**（已存在，可直接复用）
- 拖拽式节点创建和布局
- 支持多种节点类型（start、node、llm、invoke、decision、handoff、end）
- 可视化边连接（支持不同边类型：call、return、retry）
- 画布缩放、平移、自动布局
- 节点复制、粘贴、删除

**文件：`frontend/src/components/alpha/ExecutionGraphInspector.vue`**（已存在，可直接复用）
- 节点属性配置面板（节点名称、输入/输出 Schema、Prompt 配置等）
- 边属性配置（条件表达式、参数映射、结果映射）
- 图属性配置

**文件：`frontend/src/views/alpha/ExecutionTopologyTemplate.vue`**（已存在，可直接复用）
- 拓扑图模板管理页面
- 完整的 CRUD 操作（新建、编辑、删除图/节点/容器/边）
- 拓扑结构查看

**文件：`frontend/src/api/executionGraph.js`**（检查是否存在）
- 如不存在，创建拓扑图相关 API：
  - `createTopologyTemplate(data)` - 创建拓扑模板
  - `updateTopologyTemplate(id, data)` - 更新拓扑模板
  - `getTopologyTemplate(id)` - 获取拓扑模板
  - `listTopologyTemplates()` - 列出所有拓扑模板
  - `deleteTopologyTemplate(id)` - 删除拓扑模板
  - `validateTopology(data)` - 验证拓扑结构

**文件：`backend_business/api/routers/topology_routes.py`**
- 拓扑图管理 API（如已存在则复用，否则创建）：
  - `POST /api/v2/topology/templates` - 创建拓扑模板
  - `GET /api/v2/topology/templates` - 列出拓扑模板
  - `GET /api/v2/topology/templates/{id}` - 获取拓扑模板详情
  - `PUT /api/v2/topology/templates/{id}` - 更新拓扑模板
  - `DELETE /api/v2/topology/templates/{id}` - 删除拓扑模板
  - `POST /api/v2/topology/templates/validate` - 验证拓扑结构
